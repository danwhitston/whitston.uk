## Front matter — the complete key list

**Exactly one key appears across all nine posts: `title` (string).**

That is the whole schema. Specifically there is:

- **no `date:`** — dates come from the `YYYY-MM-DD-` filename prefix only
- **no `categories:`** — removed in commit `adc7155` ("Remove categories for simpler URLs")
- **no `tags:`, no `layout:`, no `author:`** (author is set repo-wide in `_config.yml` defaults)
- **no `permalink:` overrides** on any post
- **no drafts**, no `_drafts/` directory

Consequence: the schema is `{ title: string }` plus a date that must be **parsed from
the filename or written into front matter during the move**. A schema requiring
`pubDate` will fail on every post until that date is added.

## URL pattern — file-style, with `.html`

Verified against the live site:

```
/2017/05/14/browser-testing-for-ruby-from.html   200
/2017/05/14/browser-testing-for-ruby-from/       404
```

So the pattern is `/:year/:month/:day/:title.html` — Jekyll's default
`:output_ext` form. There is **no trailing-slash variant**. Astro defaults to
directory-style output and will not reproduce this; see Phase 3.

## Theme and assets

- Theme: `minima ~> 2.5` via the `github-pages` gem.
- `assets/main.css` is **compiled** minima CSS committed to the repo (not Sass with
  front matter), locally patched — recent commits add dark mode and layout fixes.
- `assets/minima-social-icons.svg` — sprite sheet for the footer icons.
- `_layouts/home.html`, `_includes/{header,footer,social}.html` — light overrides.

Per the site owner, the theme is a badly-adapted default and is **not** being carried
across. All of the above is discarded.

## `_old_site/` — dead weight

Contains favicons, `apple-touch-icon.png`, `manifest.json`, `browserconfig.xml`,
`cover.css`, a portrait JPEG, and an old `index.html`. The leading underscore means
Jekyll excludes it, and **none of it is served** (`/favicon.ico` → 404).

The favicon set is the only part worth recovering, and only if a new one isn't being
made. Otherwise delete the directory.

## Why no Jekyll build

Not attempted, and not needed. `.ruby-version` pins 3.1.2; the Gemfile pins the
`github-pages` gem (Jekyll 3.9.2, per the feed's generator tag), four years stale.
Every fact above came from reading the source or probing the live site, which is
faster and gives ground truth rather than a local reconstruction of it.
